## Политика плейтеста

Штатная сборка продолжает использовать прежнюю выдачу. Пилот включается в отдельной сборке `npm run build:issuance-pilot` с меткой `d4-v2`. Для Android используется тестовый пакет `com.danilah.crossmath.releasecheck`. Задача Gradle для стора отклоняет этот веб-пакет.

- Требуемая корзина определяется текущей позицией шестипозиционной ротации. Внутри корзины приоритет у глобально нерешённых ID. Когда таких нет, рассматривается весь пул этой корзины. Пустая корзина возвращает «недоступно» и сохраняет слот.
- Среди допустимых полей выбирается минимальное число уже записанных выдач. Предпочтение отдаётся геометрии, которой не было на трёх предыдущих позициях этой дорожки. Если выбор исчерпан, берётся форма, которую игрок видел раньше остальных. Затем идут размер класса геометрии в оставшейся группе, давность выдачи конкретного ID, более поздняя позиция в кампании и стабильный ID. Геометрия D4 учитывает числовые координаты с точностью до повернутого или отражённого рисунка. Числа, знаки и маска пропусков в неё не входят.
- Продолжение, предпросмотр, задания, повторная попытка и отказ от замены не записывают выдачу. Выбранный ID и счётчик записываются вместе с новой партией. При принятой замене общего слота Free другая дорожка сохраняет закреплённый ID. Расстановка при принятой замене сбрасывается по существующему правилу. Обычный переход в Campaign или Daily сохраняет расстановку Free целиком.
- Схема сохранения остаётся 4. Активные записи без `freeAssignmentVersion` и с версией 1 сохраняют свои ID. Формат поля с `freeAssignmentVersion=1` по-прежнему обозначает проверку корзины. Политику и назначение пилота хранит отдельная версия 2 в `meta.freeIssuance`. Для старого профиля счётчики начинаются с фактических новых назначений. Состояние ограничено одним счётчиком и последней позицией на ID плюс одним закреплением на дорожку. Верхняя граница — 225 записей на обе дорожки.
- Выигранная партия остаётся в своём слоте с квитанцией. Повтор предыдущей позиции возвращается как повтор той же партии. Текущая позиция и её счётчики от него не меняются. Цена помощи, выплаты, Daily, маршруты кампании, приостановленный Endless и 515 полей сохранены.

## Длинные серии

18 сценариев, по 360 завершений на дорожку и политику. 12 960 назначений актуального селектора сопоставлены по каждому ID с независимой [исследовательской моделью](../../porting/issuance-pilot-20261126/model.mjs). Проверены девять исходных префиксов кампании для каждой дорожки. Повтором считается расстояние до предыдущего появления того же ID или геометрии в этой дорожке.

| Метрика | Relax прежняя → пилот | Challenge прежняя → пилот |
| --- | ---: | ---: |
| Тот же ID в пределах 12 позиций, сумма по девяти сценариям | 26 → 0 | 39 → 0 |
| Тот же ID в пределах 50 позиций | 240 → 0 | 314 → 0 |
| Повтор D4 в пределах 3 позиций | 712 → 378 | 501 → 3 |
| Повтор D4 в пределах 6 позиций | 1 439 → 1 461 | 1 045 → 832 |
| Первый проход после 60 побед кампании | 75 → 120 из 120 | 105 → 105 из 105 |

На чистом префиксе минимальный промежуток до того же ID вырос **3 → 117** в Relax и **2 → 102** в Challenge. После 60 побед кампании минимум Relax вырос **12 → 60**. В этом же сценарии формы в пределах трёх позиций встречаются **78 → 45** раз, а в пределах шести **153 → 160**. Окно 3 снижает самые близкие совпадения, однако у Relax встречаются более поздние повторы форм. Это повод оценить реальное ощущение разнообразия на плейтесте.

## Смешанные сессии

Реальный `GameSession` и `SaveRepository` с управляемым временем и хранилищем. На каждый из трёх профилей и каждую политику выполнены 36 побед Free, 9 побед кампании, 6 Daily и 8 холодных восстановлений. Стартовые профили — после 15, 60 и 132 полей, оба порядка входа в дорожки. Проверены отмена, подтверждённая замена, отклонение устаревшего предложения, повтор после победы, отказ записи до коммита, потеря подтверждения после коммита, старое задание, оплаченные соседние задания и отсутствующая корзина.

Старая выдача после 132 полей выдала на той же позиции Relax `cm-own-02-001` вместо `cm-own-02-040`, когда последнее поле уже было закреплено и затем решено в кампании при переключении режима. Пилот вернул `cm-own-02-040`. За эту вторую победу базовая выплата составила 0, курсор Relax сдвинулся ровно один раз. В трёх смешанных сценариях было **1 → 0** замен ID на уже выданной позиции. В обычной сборке из этого же исходника ранее записанное закрепление распознаётся, дальнейшие позиции выдаются по штатным правилам.

## Воспроизведение и сборка

- `ISSUANCE_REPORT=.test-output/issuance16 npm test -- tests/free-issuance.test.ts` сохраняет все последовательности ID, контрольные суммы и смешанные сценарии. Исходный `model.mjs` по умолчанию воспроизводит прежние метрики. Опция `--trace` добавляет независимые последовательности для сравнения.
- `npm run check`, `npm run content:verify`, `npm run test:browser` проверяют штатную сборку, включая 515 полей Explain, существующие маршруты и рекламные сценарии. `npm run build:issuance-pilot && node tools/issuance-pilot-browser.mjs` проверяет старую расстановку, переход через Daily, отмену и принятую замену, холодный запуск на 320×568 RU/light и 390×844 EN/dark.
- `npm run build:issuance-pilot`, `npx cap sync android`, Gradle `assembleDebug assembleReleaseCheck`, затем `tools/verify-apk.py --kind releasecheck --issuance-pilot` для точного APK. Тестовая сборка устанавливается отдельно от основного приложения. Проверка на физическом Android и постоянная активация требуют отдельной приёмки.
