## MON-01 (P1) — stranded game reservation before native dispatch
Status: confirmed control-flow gap (STATIC_SOURCE); integrated failure/recovery test not run by researcher. Current unconfigured provider cannot trigger the new ad path; blocker for real provider / candidate activation.
GameSession.beginReward persists request without settlement before native call. AdsController.reward awaits beginReward then invokes show. androidAds.ts show awaits bridge.addListener('fullscreenOpened') before dispatch and returns unavailable on exceeded startBefore, or rejects on listener failure. In that case CrossmathAdsPlugin.showRewarded/journal.reserve never runs. A process crash after game commit and before native dispatch has the same split. AdsController.show catches failures/releases unopened presentation but does not persist any no-show receipt; pendingRewards enumerates native terminal receipts only. Native cancelUnopened returns closed for absent presentation but does not reconcile game request ID. canRequestReward and reserveResult reject if *any* game request has undefined settlement. A saved request with no corresponding native record is thus permanently pending unless an impossible native receipt appears; blocks all future rewarded and interstitial, including after restart, even when provider becomes available. Ordinary play and coin-paid help remain usable. Tests ads.test.ts 497–507 explicitly retain undefined settlement for unavailable; 604–615 require manually delivered late receipt; android-ads.test.ts 21–25 covers deadline without dispatch only for interstitial. These tests do not establish end-to-end recovery for never-dispatched rewarded.
Fix: durable request ownership/admission handshake/reconciliation for known-not-opened requests; cancellation fence by request ID (not mere elapsed timeout or empty receipt array). On proven never-dispatched/not-opened close or reconcile, save truthful no-reward terminal state; late dispatch must be prevented, valid earned still handled exactly once. Unknown actually-opened SDK requests retain conservative recovery. No invented grant or timer-based expiry. Include crash/lost ACK between each JS/native durable step, listener rejects/hangs/deadline, bridge rejection before invocation vs after dispatch, pre-show cancellation race, restart with absent native record vs reserved/earned/unknown native record, late earned, restored eligibility and original cooldown. Confirm no new forced show during an actually opened fullscreen and no duplicate credit. Do not weaken unknown-pending safety to make tests pass. Test in game CI and chosen native SDK separately.
