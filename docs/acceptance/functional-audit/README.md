## Storage format and crash boundaries

- Save key stays `crossmath.save.v1`, logical schema stays 4. All old flat schemas/migrations, profile identity and existing recovery/reset UI remain supported. Small saves remain ordinary JSON, preserving the common fast path. Large old saves convert on the next write; the native 4MiB/value limit is not raised.
- Above 128KiB UTF-8, serialize the exact logical state losslessly. Prefer the built-in gzip stream; a UTF-8 fallback works without CompressionStream. Leaves contain at most64KiB binary payload (under96KiB JSON), branches at most64 child hashes. A fixed manifest points at a multi-level tree; root/individual value size does not grow with Undo count. Hashes, lengths and manifest identity are checked on reads.
- No Undo cap, truncation, receipt forgetting or deletion of an unfinished Daily is introduced. Total storage necessarily retains the information in live history/receipts; this is **not** a constant-total-disk promise. Compression removes repetition, paging removes a single-value ceiling, and collection removes obsolete snapshots. The amount of genuinely distinct retained player history can still grow. Changing its user semantics requires a separate owner decision.
- Transaction order: compare every observed root/backup/quarantine value → write immutable pages → write the last-good backup → atomically replace primary → collect unreachable pages. Root publication is the linearization point. Native uses AtomicFile/fsync/readback for each value and the OS lock for the complete batch; browser uses a cross-tab Web Lock and synchronous localStorage operations inside it. A failed pre-root transaction leaves a playable previous root; a later successful commit collects orphan pages. Backup/quarantine changes are also fenced before collection. Cleanup failure does not undo a confirmed operation.
- Primary, backup and quarantined page trees are retained. A corrupt quarantine postpones collection rather than deleting evidence. A reader straddling a changed root retries; an unavailable page read is propagated, never treated as a new install or permission to roll back. Missing/damaged page data can recover a validated backup with the original confirmation/reset rules. Future schemas/encodings remain protected.
- Lost ACK: recognize only the exact durable root sent. A different or unreadable root requires recovery, never a speculative success/reward. Old pending/earned/ACK and receipt tests remain intact.
- Injected in-memory test adapters share an identity lock; actual shipped storage always implements native CAS or browser Web Locks. Web without Web Locks fails closed. Old and new APK code are tested sequentially, with retained storage; simultaneous uncooperative old-version browser writers are not a supported synchronization protocol. No cloud merge is added.
